# 自動取り込みパイプライン（watch → ingest → PR）

> 対応表の実装は `scripts/lib/session-id-rules.ts`。**このドキュメントと実装が食い違ったら実装が正**。
> 表を足したら、ここも同じコミットで直すこと。

新着動画の検知から PR 作成までを GitHub Actions で走らせる。人間に残る仕事は **PRレビューだけ**。

```
[watch-council]  RSS監視 → Issue「[新着動画] 令和8年9月18日 定例第3回 最終日」
       │ 同じワークフローから続けて呼ぶ
       ▼
[auto-ingest]    Issueタイトル → 対応表で推定 → 字幕 → Claude抽出 → build:data → 検証
       │                                  │
       │                                  ├─ 表に無い       → Issueにコメントして停止（推定しない）
       │                                  ├─ 字幕が未生成    → 保留、翌日以降に再試行（5日で諦め）
       │                                  └─ 字幕が恒久無効  → Issueに報告して終了
       ▼
 auto/session-{id} ブランチ = 1セッション1本 → PR（reviewed: false）
       │ 人間: 推定の根拠と固有名詞・数値を確認 → reviewed: true → マージ（Issueは自動で閉じる）
       ▼
 マージ後に必要なら npm run cards:generate
```

## 表1 — 会議名 → セッションID

Issue タイトルの2ブロック目（`令和8年9月14日 **決算特別委員会** 午前`）で引く。

| 会議名 | セッションID | 会議種別/議案種別タグ | officialTitle |
|---|---|---|---|
| `定例第{N}回` | `r{元号年}-{西暦}-{月}-regular-{N}` | 定例会 | `令和{元号年}年第{N}回新得町議会定例会` |
| `臨時第{N}回` | `r{元号年}-{西暦}-{月}-rinji-{NN}` | 臨時会 | `令和{元号年}年第{N}回新得町議会臨時会` |
| `決算特別委員会` | `r{元号年}-{西暦}-{月}-kessan-tokubetsu` | 特別委員会, 決算 | `令和{元号年}年{月}月{日}日 決算特別委員会（令和{元号年−1}年度）` |
| `予算特別委員会` | `r{元号年}-{西暦}-{月}-yosan-tokubetsu` | 特別委員会, 当初予算 | `令和{元号年}年{月}月{日}日 予算特別委員会（令和{元号年}年度）` |
| 上記以外 | **推定しない**（Issueにコメントして停止） | | |

**年度の向きが会議で逆になる。** 9月の決算特別委員会は前年度決算の審査なので `元号年 − 1`、
3月の予算特別委員会は当年度予算の審査なので `元号年`。制度上の必然であって推測ではない。

テーマタグ（医療・インフラ等）は自動では付けない。実際に議論された論点はレビューで足す。

**既存セッションへの合流**: 推定IDが無くても、同じ月・同じ種別のセッションが日付入りIDで
既にあれば（例: 推定 `r8-2026-01-rinji-01` / 既存 `r8-2026-01-27-rinji-01`）そちらに合流する。
候補が2つ以上あるときは推定しない。

## 表2 — パート名 → part / 種別

3ブロック目（`令和8年9月14日 決算特別委員会 **午前**`）で引く。`{n}` は既存パート数＋1。

| パート名 | part | type | label | 適用できる会議 |
|---|---|---|---|---|
| `初日` | `day{n}` | honkaigi | `初日（9/1）` | 定例会・臨時会 |
| `本会議` | `day{n}` | honkaigi | `本会議（4/7）` | 定例会・臨時会 |
| `一般質問` `一般質問②`… | `day{n}` | qna | `一般質問②（9/16）` | 定例会・臨時会 |
| `最終日` | `day{n}` | honkaigi | `最終日（9/18）` | 定例会・臨時会 |
| `午前` | `part{n}` | qna | `午前` / `2日目 午前（3/17）` | 特別委員会 |
| `午後` | `part{n}` | qna | `午後` / `2日目 午後（3/17）` | 特別委員会 |
| 上記以外 | **推定しない**（Issueにコメントして停止） | | | |

会議と合わない組み合わせ（定例会に `午前`、特別委員会に `最終日` 等）も推定しない。

### `最終日` は日付も動かす

`最終日` のパートを足したときだけ、`session.yaml` を次のように更新する（スキーマ §2.1）。

- `date` ← 最終日の日付（会期を代表する日）
- `sortDate` ← 会期初日（既存 parts[0] の開催日）

これで会期中に開かれた特別委員会との並び順が実時間どおりになる。
`初日` や `一般質問` の追加では `date` を動かさない。

### 日付はタイトルから取る

RSS の公開日は使わない。議会はライブ配信枠を数日前に作ることがあり、公開日が開催日より
前に出る（実例: 9/14 の決算特別委員会の枠が 9/11 に作られた）。配信が終わると公開日は
開催日に更新されるため、**タイトルの日付が唯一一貫している値**になる。

タイトルは全角数字・全角空白で書かれ、まれに全半角が混ざる（実例: `令和８年９月１4日`）。
比較の前に必ず正規化する。

## 停止したときの読み方

| 状態 | どこに出るか | 次にやること |
|---|---|---|
| 推定不能 | Issueコメント + Telegram | 表に足す（このドキュメントも直す）か、`npm run add-session` で手動取り込み |
| 字幕が未生成 | 状態ファイル（初回だけ Telegram） | 何もしない。翌日12:00 JSTに再試行する |
| 字幕待ちを諦めた | Issueコメント + Telegram | 字幕が付いてから auto-ingest を手動実行 |
| 字幕が恒久的に無効 | Issueコメント | そのパートは字幕から取れない。PDFスライド等で代替する |
| 抽出・検証に失敗 | Issueコメント + Telegram | ログを見て対処。`content/` は処理前に戻っている |

**同じ会期の後続パートは、先行パートが入るまで進めない。** `day{n}` の採番が
「既存パート数＋1」である以上、順序が崩れると番号がずれるため。

## 冪等と安全弁

- 動画URLが既に `session.yaml` にあれば何もしない。同じ Issue を何度流しても増えない
- 既存パートは上書きしない（`partIndex` は常に既存パート数。埋まっていたら停止）
- 失敗したら `session.yaml` とMDを処理前に戻す。`transcripts/` は残す（Layer 0・再取得が高い）
- 生成物は必ず `reviewed: false`。`cards:generate` はここでは走らせない（レビュー後の工程）

## 手で動かす

```bash
npm run auto-ingest -- --dry-run            # 推定だけ見る（何も書き込まない）
npm run auto-ingest -- --issue 17           # Issue #17 だけ処理する
npm run auto-ingest                          # 開いている [新着動画] Issue をすべて処理
```

Actions からは `Auto Ingest Sessions` を `workflow_dispatch` で実行（`dry_run` / `issue` を指定できる）。

## 必要な Secrets

| 名前 | 用途 | 無いとどうなるか |
|---|---|---|
| `ANTHROPIC_API_KEY` | 字幕→MDの抽出、narrativeTitle の3案 | 取り込みが失敗する（必須） |
| `TELEGRAM_BOT_TOKEN` | 通知 | 通知だけスキップ。取り込みは動く |
| `TELEGRAM_CHAT_ID` | 通知の宛先 | 同上 |
| `YOUTUBE_API_KEY` | RSSが弾かれたときの新着検知（既存） | RSSが通れば不要 |
| `GITHUB_TOKEN` | Issue・PR・push（Actionsが自動発行） | 設定不要 |

`GITHUB_TOKEN` でPRを作るには、リポジトリ設定
**Settings → Actions → General → Workflow permissions** で
「Allow GitHub Actions to create and approve pull requests」を有効にしておく必要がある。

## 状態ファイル

`data/watch/ingest-state.json` — 動画IDごとに「機械が次に何をするか」だけを持つ。

| status | 意味 | 再試行 |
|---|---|---|
| `done` | 取り込み済み | しない |
| `pending` | 字幕待ち | する（翌日） |
| `gave_up` | 字幕待ちを諦めた | しない |
| `disabled` | 字幕が恒久的に無効 | しない |
| `blocked` | 対応表で推定できない | する（表を直せば次で進む） |
| `failed` | 抽出・検証に失敗 | する |
