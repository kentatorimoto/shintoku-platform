# Claude Code 実装指示書 — 郷土資料の統合と /shiseki（概要レベル公開）

> **目的**: `ryuiki-archive` の2冊（郷土読本くったり／しんとくの史跡）を SHINTOKU ATLAS に統合し、史跡27件を**概要レベル**で公開する。将来の「町に聞く」（RAG）の土台も同時に整える。
>
> **ATLASの思想との接続**: 設計思想 §7「将来的な射程：地形・交通・産業・流域・歴史へと接続していく」の実装。議会記録が「町がいま何を決めているか」なら、これは「町がどうしてこうなったか」。両者は固有名詞（狩勝・屈足・十勝川）で接続する。
>
> **前提となる方針変更**: `ryuiki-archive/README` の「汎用LLMへの投入禁止」は「Claude API（Anthropic）への送信は可。ただし公開する出力は引用最小限＋出典ページ必須」に改訂済みとして進める（この改訂もPhase 0に含む）。
>
> **権利の状態**: 発行元への確認は**継続検討中**。したがって本実装は「許諾がなくても守れる範囲」＝**概要レベル**に限定する。OCR全文は公開しない。

---

## 権利ガードレール（全Phaseに優先。破ってはならない）

1. **本文全文をUIに出力しない。** 公開するのは、史跡ごとの「所在地・年代・2〜3文の概要・原本ページ番号」まで
2. **概要は要約であって引用ではない。** 原文の語順・言い回しをなぞらず、事実を自分の言葉で再構成する（ATLASの copyright 規律と同じ）。固有名詞・数値・年代は原文どおり
3. **各ページに必ず出典表記**: 『しんとくの史跡』新得町郷土研究会・1994年・p.◯／新得町図書館蔵。「原本は新得町図書館で読めます」の一文を添える
4. **OCR全文（`content/archive/**/*.md` の本文）は `public/` に出力しない。** ビルド時にJSONへ変換するのは、公開対象のメタと概要のみ
5. 図版（写真・地図・イラスト）は**掲載しない**。`visual_elements` はメタとして保持するが、画像自体は archive に残す

## Phase 0: 移送と整理

1. `ryuiki-archive` から ATLAS へ、**MDとYAMLのみ**を移す（PDF・`.venv`・`_staging`・`test_pages`・`results` は移さない）:

```
content/archive/
  kuttari-kyodo-tokuhon/
    book.yaml            # 書誌（共通メタ・後述）
    ch01.md 〜 ch10.md    # 各章（frontmatter は source_ref のみ）
    matome.md / sanko.md
  shintoku-shiseki/
    book.yaml
    site_map.yaml        # 27件のインデックス（既存を移送）
    s01.md 〜 s27.md      # 1史跡1ファイル
```

2. **frontmatter の外出し（重要）**: 各章/史跡が書誌情報・編纂者一覧・権利表記を丸ごと繰り返している状態を解消する。共通メタは `book.yaml` に集約し、各MDの frontmatter は以下だけにする:

```yaml
---
source_ref: shintoku-shiseki-v1   # book.yaml への参照
id: s14
title: 旧狩勝トンネル
page_start: 22
confidence: confirmed              # confirmed | check（既存の site_map.yaml 準拠）
reviewed: false                    # 人間確認フラグ（議会側と同じ規律）
entities: [狩勝, 旧狩勝線, 新内]    # 議会記録との接続キー（後述 Phase 3）
era: 明治後期〜昭和                 # 年代（分かる範囲。不明なら省略）
location: 新得町字新内              # 所在地（原本の記載どおり。番地は落とす）
summary: |                         # 公開する2〜3文。Phase 2 で作成
  （未作成）
visual_elements: [...]             # 既存のまま保持（公開はしない）
---
```

3. OCR注記（`> [!note] OCR注記`）と校異の記録は**本文にそのまま残す**。これは archive の美点であり、議会側の `【要確認】` と同じ役割
4. `ryuiki-archive/README` の方針文を改訂（前述）。改訂の理由と日付を残す
5. 移送後、`ryuiki-archive` は**素材リポジトリとして残す**（PDF原本とOCRパイプラインの置き場）。ATLAS 側は正典MDのみを持つ

## Phase 1: ビルド統合

1. `scripts/build-data.ts` に archive の処理を追加。既存のセッション処理と**同じ規律**:
   - `book.yaml` と各MDの frontmatter を検証。必須フィールド欠落・`confidence` の不正値は **exit 1**
   - 出力は `public/data/archive/shiseki.json`（27件のメタ＋概要のみ。**本文は含めない**）
   - `stableStringify` を通す。`public/data/` は生成物という既存の原則を維持
2. `scripts/lib/schema.ts` に `ShisekiItem` / `BookMeta` 型を追加
3. `docs/content-schema.md` に §12「郷土資料（archive）」として、上記スキーマと**権利ガードレール**を明記する

## Phase 2: 概要（summary）の作成

1. `scripts/generate-shiseki-summary.ts` — 各史跡MDの本文から、公開用の2〜3文の概要を Claude API で生成する。プロンプトは `scripts/prompts/shiseki-summary.md`:
   - **事実の再構成のみ**。評価語・情緒的形容を使わない（「趣がある」「貴重な」等は禁止）
   - 原文の言い回しをなぞらない。ただし固有名詞・年代・数値は原文どおり
   - 読者は郷土史を知らない町民。中学生が読める語彙で
   - 「いつ・どこで・何があった場所か」を必ず含める
   - 原文にない事実を足さない。不明な点は書かない
2. 生成後 `reviewed: false` のまま。**Kentaのレビューを経て `true`**（議会カードと同じゲート）
3. まず **3件だけ生成して提示し停止**。トーンの基準を作ってから残り24件（議会カードのときと同じ進め方）

## Phase 3: /shiseki UI

1. `/shiseki` 一覧 — 27件を掲載順（`site_map.yaml` の order）で。各行に史跡名・所在地・年代・原本ページ。デザインは既存トークン（緑灰・茜・図郭・Space Mono の番号）
2. `/shiseki/[id]` 個別 — 史跡名（明朝）／所在地・年代／**概要2〜3文**／出典表記（発行元・年・ページ・図書館蔵）／`confidence: check` の項目には「原本と照合中」の注記
3. **本文・図版は出さない**（権利ガードレール1・5）
4. ナビへの追加は `About` の隣ではなく、**「流れを読む」の系列**として扱う（意思決定の構造を、時間の深さ方向へ延長したもの）。ラベルは翻訳層（`lib/labels.ts`）で管理し、案は「土地の記憶」または「史跡を読む」
5. 一覧に地図は**今回は載せない**（Leaflet導入は別PR。まず読み物として成立させる）

## Phase 4: 議会記録との接続（このPRの核心）

1. 各史跡の `entities`（狩勝・屈足・十勝川・旧狩勝線 等）を使い、**既存の全文検索インデックスと突き合わせる**
2. 史跡ページの末尾に「**この場所は議会でも議論されています**」として、該当セッションへのリンクを最大3件（例: 旧狩勝トンネル/狩勝ポッポの道 → 令和8年9月定例の橋梁補修）
3. 逆方向は**今回やらない**（議会側UIへの追加は別PR。まず片方向で成立を確認）
4. 接続は `entities` の完全一致のみ。あいまい一致や推論はしない（誤った関連付けは観測装置の信頼を損なう）

## 受け入れ基準

1. `content/archive/` が正典として存在し、frontmatter の重複が解消されている（本文＋メタで概算11万トークン以下）
2. `build:data` が archive を検証し、`public/data/archive/shiseki.json` を生成する。**本文が含まれていないこと**を grep で確認
3. `/shiseki` と `/shiseki/[id]` が既存デザイントークンで表示され、全ページに出典表記がある
4. 少なくとも1件の史跡に、議会セッションへの接続リンクが表示される
5. 全ページSSG成功。既存の議会側の機能・データに一切の変更なし
