# Claude Code 実装指示書 — 会議録を土台にした「構造化」への転換（試作）

> **方針転換（2026-11-01）**: ATLAS は「記録を早く作る」ことから手を引き、「意思決定の流れと構造をあぶり出す」ことに注力する。
> 正確な記録は町の公式会議録（平成22年〜、テキストPDF、公開は閉会から約2.5か月後）が担う。ATLAS はそれを材料に、**会議録を1本ずつ読んでも見えない、年をまたいだ論点の流れ**を作る。
>
> この指示書は試作の範囲。**Phase B の試作1本を私（健太）が読んで判断するまで、本格展開しない。**

---

## 背景（調査済みの事実）

- 会議録ページ: https://www.shintoku-town.jp/gyousei/gikai/kaigiroku/ （年ごとの索引。平成22年〜令和8年、17年分）
- 令和8年は臨時第3回（7/6）まで公開。9月定例は 11/1 時点で未公開
- 形式: 会議ごとに1本のPDF（一太郎で作成）。テキストPDFで `pdftotext` で文字化けなく取れる。1本あたり約65〜70ページ・約7万字
- 発言は「◎氏名議員（議長）」で始まり、「日程第〇」の見出しがある → 発言者・議事日程ごとに機械で分割できる
- 目次・名簿は字間に空白が入る（「新 得 町 議 会」）。全角文字どうしの空白は潰す（広報索引で使った処理と同じ）

## ガードレール

- **既存の動画パイプライン（watch-council / auto-ingest）は止めない・手を入れない。** 今後の扱いは試作の結果を見て決める
- **会議録PDFは `public/` にもリポジトリにも置かない。** 置くのは抽出したテキストだけ（Layer 0）。PDFは町のURLを参照する
- UIに会議録の全文は出さない。出すのは流れの記述と、各項目の出典（町の会議録PDFのURL＋ページ）
- 書くのは事実の再配置だけ。評価語・推測・因果の断定をしない（ATLASの規律と同じ）
- Claude API は残高が少ないので、全文を投げない。キーワードで抜粋してから渡す。実行前に見込み額を報告すること

---

## Phase A: 会議録コーパスの取り込み

1. `scripts/kaigiroku/fetch-index.ts` — 会議録ページから全年の会議一覧（会議名・会期・PDFのURL）を取得し、`data/kaigiroku/index.json` に保存
2. `scripts/kaigiroku/extract.ts` — 各PDFを一時取得 → `pdftotext` → 全角空白を正規化 → 「日程第〇」「◎氏名」で分割し、次の形で保存（PDFは保存しない）
   ```
   content/kaigiroku/{sessionKey}/raw.txt        # 抽出した全文（Layer 0・変更禁止）
   content/kaigiroku/{sessionKey}/speeches.json  # [{agenda, speaker, role, page, text}]
   ```
   `sessionKey` は既存の命名（`r8-2026-06-regular-2` 等）に合わせる。既存セッションとの対応表も作る
3. まず令和元年〜令和8年分だけ取り込み、件数・総文字数・分割できなかった箇所を報告して停止（平成分はその後）
4. あわせて小さな修正：`r8-2026-06-regular-2` の「田中副町長」を会議録の説明員一覧に基づき **畑中栄和副町長** に修正し、glossary の理事者・課長表を会議録の名簿で更新（会期ごとに課名が変わる点に注意）

## Phase B: 論点の流れの試作（1本）

**テーマ：駅前の再整備（駅前広場 → 複合施設「とくとく」→ 温浴宿泊施設・町営浴場・金融機関の併設）**

1. `speeches.json` からキーワードで発言を抜粋（駅前・複合施設・地域交流センター・とくとく・温浴・町営浴場・金融機関・指定管理 など。表記ゆれを含める）。抜粋件数と、どの会議に何件あったかを先に報告
2. 抜粋を年代順に Claude に渡し、流れを組み立てる。出力は `content/traces/ekimae.md`（`reviewed: false`）。中身：
   - 最初に議会で出たのはいつか、誰の発言か
   - 主な節目（構想・計画・予算・契約・着工・開所・延期・白紙）を時系列で
   - 論点の枝分かれ（とくとく本体／温浴宿泊施設／町営浴場／金融機関／指定管理）
   - 各節目に必ず出典：会議名・日付・発言者・町の会議録PDFのURLとページ
   - 繰り返し出てくる問いや、答弁が変わったところがあれば、事実として並べる（評価しない）
3. ページ `/process/traces/ekimae` を作る。既存の「とくとく」トレース図（`/process/issues/tuktuk`）を土台に、期間を平成〜令和に広げた形。デザインは現行トークン
4. **ここで停止。** Preview URL と `ekimae.md` を報告。私が読んで「これは読みたいか」を判断する

## 報告してほしいこと

- Phase B: 抜粋件数、API の実費、流れの節目の数、出典の付いていない記述がゼロであること
