# 論点の流れの event スキーマ

`content/traces/{theme}.events.json` の定義。COTEN 世界史データベースの設計（史実・解釈・メタ解釈の3層、行為中心の出来事、述べられた因果のつながり）を参考に、議会の会議録に合わせた。

**1発言の1引用が1件。** 同じ事柄で答弁が食い違っていても寄せず、別の event のまま持つ。並べるときは `groups` を使う。

生成: `npm run kaigiroku:events -- ekimae`（API は呼ばない）／検査: `npm run kaigiroku:verify-events -- ekimae`

## フィールド

| フィールド | 内容 | 空になるとき |
|---|---|---|
| `id` | `ev-0001` 形式。発言日・ページ順。再生成で変わるので外部から固定で参照しない | なし |
| `layer` | 下の3層 | なし |
| `action` | 正規化した行為（下の語彙） | fact で語に当たらないとき `null` |
| `action_phrase` | `action` を決めた原文の語 | 受け皿（質問・説明）のとき `null` |
| `tense` | `実施` / `予定` | 文から読み取れないとき `null` |
| `actor` | `{name, role}`。出典の発言者 | なし |
| `objects` | とくとく本体・温浴宿泊施設・町営浴場・金融機関・指定管理・駅前広場（複数可） | 文にも生成結果にも手がかりが無いとき `[]` |
| `object_source` | `text`（原文の語）/ `parent`（生成結果の分類を流用） | `objects` が空のとき `null` |
| `date` | 発言した日 | なし |
| `stated_date` | 発言とは別の日の出来事として生成結果が置いた日 | 同じ日のとき `null` |
| `amounts` | `{raw, yen, approx}`。その一文に書かれた金額だけ | 無ければ `[]` |
| `causes` | 下の因果 | 無ければ `[]` |
| `source` | `excerpt_id`・`session_key`・`speech_index`・`page`・`url`・`agenda`・`quote`・`sentence` | `excerpt_id` は議決の発言だけ `null` |
| `bill` / `result` | 議案番号と採決結果。speeches.json で確かめられたものだけ | 一括議題・議案以外は `null` |
| `groups` | 同じ事柄のまとまりの名前（`問い: …` / `答弁: …`） | 無ければ `[]` |
| `derived_from` | 生成結果のどの項目から来たか | なし |

## layer の決め方

**発言者の役職が先に決まる。** 内容で議員の発言を interpretation にすることはない。

| 発言者 | layer |
|---|---|
| 議員・委員 | `debate`（質問・異論） |
| 議長・委員長など議事を進める役 | `fact`（採決・議事の進行） |
| 町（町長・副町長・課長など） | 金額がある文と、行為が確かなもの（白紙・延期・増額・減額・契約・契約変更・開所・閉鎖・着工・完成・条例制定・指定・用地取得・予算計上）は `fact`。**理由が添えられていても行為は fact で、理由は `causes` に持つ。** それ以外で理由や考えを述べる文は `interpretation` |

`fact` は「議決・日付・金額・提案」を述べた発言であって、その内容が真実だと保証するものではない。

## action の語彙

`白紙`・`延期`・`議決`・`増額`・`減額`・`契約変更`・`契約`・`開所`・`閉鎖`・`着工`・`完成`・`条例制定`・`指定`・`用地取得`・`予算計上`・`調査`・`計画`・`構想`、受け皿として `質問`（debate）・`説明`（interpretation）。

言い回しとの対応は `content/traces/action-normalization.json`（語彙の全件と今回の出現数）、語彙の定義は `scripts/kaigiroku/event-schema.ts`。引用の中の語を優先し、無ければ一文全体を見る。語が複数あれば語彙の上にあるものを取る。

## causes（因果）

会議録の中で理由として述べられたものだけ。推測で足さない。

| フィールド | 内容 |
|---|---|
| `reason` / `effect` | 理由と結果の原文 |
| `marker` | つなぎの語（ことから・の影響を受け・に伴い 等） |
| `certainty` | `断定` / `推測`。理由の部分に推量の語（と考え・見込み 等）があれば推測 |
| `hearsay` | 述者自身の説明でなく、他者の説明や文書を引いたもの |
| `scope` | `同じ文` / `前の文`。前の文を見るのは増額・減額・延期・白紙・契約変更だけ |
| `stated_by` | 述べた人 |

「に伴い」を理由と読むのは増額・減額・延期・白紙・契約変更だけ。拾わないもの: 条例提案などの定型文の「〜に伴い」、「〜するため」（目的）、「規定により」「ことにより」（根拠・手段）、議員の「〜なので質問します」。議員の発言は、町や文書の説明を引いた文だけ `hearsay: true` で残す。

## 検査（verify-events）

出典の `speeches.json` に照らして次を確かめる。判定は build-events のコードを使わない。

- `actor` が出典の発言者と一致する
- **議員の発言は debate のみ、議員以外は debate にしない、議長は fact のみ**
- 日付・議事・引用・一文が出典の本文にある。URL とページが一致する。抜粋IDが同じ発言を指す
- `action` と `objects` が語彙の中にある。`action_phrase` が一文にあり対応表と一致する
- 金額・因果が原文にある。`certainty` がある。議員の発言の因果は伝聞になっている
- 採決結果は議長の発言にあり、議案番号を含む
