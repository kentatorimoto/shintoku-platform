修正を受けたら、同じ失敗を防ぐ規則として書き足す。日付は絶対日付で書く。

## 2026-08-16 要点カードの語彙と kind

- **`decision` は議案の採決結果に限る。** 行政報告に由来する事実は `report`。
  「決まったこと」を広く取ると、採決を経ていない報告（例: 帯広信用金庫の増設保留）が
  「議会が決めた」ように読める。カテゴリの誤りは、事実の誤りと同じ重さで扱う。
- **程度・新規性の修飾語（「新」「刷新」「大幅」）は、MD本文にその語がある場合のみ使う。**
  「農業委員11名が新体制に」は再任を含むので事実に合わなかった。
  要約で語彙を足すと、MDにない含意が混ざる。
- 出来事が複数パートにまたがるときは、どのパートの出来事かが読者に分かるように書く
  （「6/3に報告され、6/19の質疑で理由が説明された」）。
- → 規律は `scripts/prompts/cards.md` に、定義は `docs/content-schema.md` §11 に書く。
  プロンプトだけ直してスキーマを放置しない。

## 2026-08-16 外部依存のフォールバックは、壊して確かめる

`OGPフォントの取得に失敗してもビルドは止めない` と設計してコメントにもそう書いたが、
実際に取得URLを壊して試すと **satori はフォントが1つも無いと "No fonts are loaded" で落ち、
ビルド全体が失敗した**。フォールバック経路は、実際にその状態を作って通してみるまで
「動くはず」でしかない。ドキュメントに書く前に、壊して実行する。

（対策として Space Mono を `assets/fonts/` に同梱した。1つでも渡っていれば版面は成立する。）

## 2026-08-16 並列ビルドと外部フェッチ

`next build` は複数ワーカーで静的ページを作る。各ワーカーが同じ大きなファイル（5.4MB のフォント）を
同時に取りにいくと取得が壊れる（fontkit が "Bad flags"）。ビルド前に1回だけ取得して
ローカルに置き、ワーカーは読むだけにする。

## 2026-09-16 コントラストは「紙の上」だけで測らない

透過付きテキストの棚卸しをしたとき、`tasks/todo.md` の実測表は紙（`base`）の上だけで
測っていた。実際には `.card` が `bg-ink` で、カード地の上では `textSub` が 4.24:1 と
元から未達だった。**同じユーティリティが複数の面に載るなら、いちばん不利な面で測る。**

→ `scripts/check-contrast.ts` は、地色が書かれていない文字を
紙とカード地の**両方**に対して検査する。片方だけ通ってもエラーにする。

## 2026-09-16 「一段薄い色」は輝度の余地を計算してから提案する

「AA を保ったまま、もう一段薄い階調を足す」は一見もっともらしいが、
`textSub` が既に 4.58:1 なら余地は RGB 1段しかない（輝度上限 `L=0.138599` に対し
`textSub` が `L=0.135224`）。作っても見分けがつかない。
**階調を1段足す提案が来たら、まず上限輝度を計算して余地があるか確かめる。**
余地が無ければ、そのことを数字で示してから代案（3段の組み直し／サイズと余白）を出す。

## 2026-09-16 色トークンの名前は Tailwind のユーティリティと衝突する

`--color-base` を定義すると Tailwind 4 は `.text-base { color: … }` を生成し、
本来の文字サイズ `text-base`（1rem）を潰す。ソースを読むだけでは気づけず、
**ビルド後のCSSを見て初めて分かった**（`.text-base{color:var(--color-base)}`）。

→ 色トークンに `base` / `sm` / `lg` / `xl` など Tailwind のスケール語を使わない。
紙の色は `paper` に改名した。ユーティリティの解決結果が怪しいときは
`.next/static/chunks/*.css` を grep して確かめる。

## 2026-09-16 パレットの二重管理は必ず片方が古くなる

`lib/og.tsx` が「globals.css と同じ値。片方だけ変えないこと」とコメント付きで
パレットを書き写していた。コメントがあっても、階調を入れ替えたときに古い値が残った。
satori は Tailwind を通らないので値そのものが要るが、**ビルド時に `globals.css` を
読めば済む**話だった。書き写す代わりに読む。

## 2026-09-16 静的検査を書いたら、実描画でも測って突き合わせる

`scripts/check-contrast.ts` は「透過0件・AA未達0件」と報告したが、本番を Playwright で
実測したら `/announcements` の NEW バッジが **2.58:1** だった。

原因は、`bg-accent text-base …` の `text-base` が**紙色のつもり**で書かれていたこと。
`--color-base` を `--color-paper` に改名した結果 `text-base` が文字サイズに戻り、
バッジが親から `textMain` を継承して墨色になった。
静的検査は「文字色の指定が無い要素」を見ていなかったので素通りした。

→ 検査に「茜の面を敷いて文字色を書いていない要素」を足した。
→ **トークンを改名したら、その名前を"色のつもり"で使っていた箇所を全部洗う。**
   改名で意味が変わる指定は、消えるのではなく別の意味に化ける。

## 2026-09-16 算出色を自前で解析しない

Tailwind 4 の不透明度は `color-mix(in oklab, …)` なので、`getComputedStyle` は
`oklab(0.926928 -0.00558683 0.0150194 / 0.8)` を返す。`/[\d.]+/` で数値を拾うと
負号が落ち、0〜1 の値を 0〜255 として読んで**ほぼ黒**になる。
最初の実測で AA 未達5件と出たが、全部この誤読だった。

→ 色の解決はブラウザにやらせる。canvas に順に塗って `getImageData` で読み戻せば、
記法にもアルファ合成にも依存しない。
