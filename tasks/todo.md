# 郷土資料の統合（PR `feat/archive-shiseki`）

## 積み残し: 歴史的呼称と現代呼称の対応表を別レイヤーで持つ

史跡と議会記録の接続（スキーマ §12.7）は **`entities` の完全一致のみ**で、現在つながるのは
26件中2件（`s10` トムラウシ／`s23` 新得山）。仕様書が例示した
「旧狩勝トンネル → 令和8年9月定例の狩勝ポッポの道の橋梁補修」は成立しない。

原因は語彙のずれで、データの不備ではない:

| 原本（1994年） | 議会記録（2026年） |
|---|---|
| 狩勝峠 / 旧狩勝線 / 新内トンネル | 狩勝高原整備費 / 狩勝ポッポの道 |
| 旧狩勝牧場 | （給水設備の光熱費として言及） |
| 上川灌漑溝十勝川水門 | （現存せず。昭和53年に通水終了） |

**`entities` に「狩勝ポッポの道」を足す案は採らない**（2026-09-09 判断）。
原本にない語を正典に書き足すことになり、「原本は原本として保全する」という
ryuiki-archive の原則と、ATLAS の「事実の再配置のみ」の規律に反するため。

### 代わりに検討する案

**歴史的呼称 ↔ 現代呼称の対応表を、資料からも議会記録からも独立した第3のレイヤーとして持つ。**

```yaml
# 案: content/archive/place-aliases.yaml（正典ではなく索引）
- canonical: 狩勝
  historical: [狩勝峠, 旧狩勝線, 狩勝トンネル, 狩勝国境]
  current: [狩勝高原, 狩勝ポッポの道, 狩勝峠園地]
  note: 旧狩勝線の廃線敷が遊歩道「狩勝ポッポの道」として整備された
  confidence: check          # 対応関係の確度も持つ
```

- どちらのレイヤーにも語を足さず、**対応関係だけを別に記録する**。原本も議会記録もそのまま残る
- 接続時は「原本の語 → canonical → 現代の語」で引く。UIでは根拠として
  「旧狩勝線（現在の狩勝ポッポの道）」のように**変換の経路を見せる**
- 対応表自体に `confidence` を持たせ、推定を含むものは `check` として区別する
  （史跡の `confidence: check` と同じ思想）

判断が要る点:
- 誰がこの対応表を書くか（原本にも議会記録にも書かれていない知識であり、**編集者の判断が入る**）
- 入れる範囲。地名だけか、施設・制度（駅逓所→道の駅、灌漑溝→用水路）まで広げるか
- 「町に聞く」（RAG）でも同じ対応表が要るはずなので、その設計と一緒に決めるのが自然
